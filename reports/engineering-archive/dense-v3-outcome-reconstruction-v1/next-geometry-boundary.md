# Next local reconstruction surface — not implemented or accepted here

The completed outcome calculation supplies all original scores and validation-selected recipes.
Its own numerical replay is distinct from the existing vector-to-feature reader. The next missing
consumer must connect these with the original geometry and bridge evidence, not rerun completed
kernel diagnostics or replace original features with the newer four functional predictors.

Inspected interfaces:

- `primary_v3_geometry_io.descriptor` is path-neutral: actual recipe/run identity, all five
  checkpoint file inventories, complete reference identity and frozen geometry settings.
- Each `geometry/runs/<run_id>` has one manifest and five JSON/basis pairs. A local reader must
  require exactly twelve runs and all five stages, both displacement kinds and the original
  88 hidden-matrix population. Match this population to the same authenticated vector/outcome
  run metadata; never join runs only on optimizer names or learning rates.
- Saved stage JSON contains raw matrix metrics, exact changed-entry counts, recorded subspace
  health and a derived `checkpoint_row`. Recompute the latter with the unchanged
  `primary_geometry_kernels.checkpoint_row`; compare fresh derived values, not stored aggregates.
- `read_stage_bases` explicitly assumes prior numeric admission. It is not a complete standalone
  validation gate: it checks paired left/right presence but not all tensor names, dtype, shape,
  finiteness, metadata or agreement with recorded zero/nonzero health. Add complete schema and
  identity checks before using it on the local archive. Do not invent a new scientific rank/gap
  threshold or silently change the previously frozen validity rules.
- `tables_from_verified_runs` can recompute the 60 checkpoint rows, 660 pair overlaps and 60
  optimizer summaries. Its 10,560-row health table retains authenticated measurement records;
  it does not freshly estimate the displacement spectrum from the stored bases.

Crucial evidence boundary: projected numerical rank, threshold, smallest/next singular values,
boundary gap and retained Frobenius energy come from the original displacement-matrix SVD/sketch.
Bases alone do not identify those quantities. A local summary consumer can authenticate them,
check typed/complete/consistent coverage and recompute overlaps and aggregations. It must keep
`raw_weight_metrics_recomputed` and `spectral_health_remeasured` false. Actual fresh weight-to-
metric verification needs the separately retained model/checkpoint payloads and original reader.

The next bridge must retain all nine original features and the separate exact-spectrum sensitivity
family. The existing `bridge_tables` combines reconstructed geometry with reconstructed stage
scores; exact identifiability, all dose/stage folds and undefined outputs are already frozen.
Only after original and functional inference/rendering are reconstructed from their complete
local inputs can final primary publication be considered. Same-host synthetic replay, recorded
primary metadata and statistical preparation still do not admit actual primary results.

Do not implement this surface until the original-outcome milestone has terminal tests, an
independent replay and a source-bound acceptance record. Formal source release, controller
transition and primary execution remain separately gated by the root agent instructions.
