# Complete-paper numerical reconstruction handoff

This CPU-only successor will wait for the existing actual complete-document
consumer. It will not duplicate evaluation, the native statistical collectors,
document authoring, training, checkpoint backup or GPU resume verification.

The completed primary closure is reused unchanged as a nested input. Once all
actual factorial outcomes and the native strict paper are complete, assemble a
new closed package containing their original native receipts, complete numerical
inputs, unchanged statistical/renderer source and paper sources. In a fresh
CPU process, replay the complete primary graph and all six factorial tables,
retain the original independent arithmetic check, regenerate all four paper
includes and both empirical figures, and freshly compile the complete paper.
Compare generated bytes, all numerical outputs, source/float/page/font gates
and extracted PDF text with the actual native paper. The full PDF binary may
contain compilation metadata; do not substitute binary identity for these checks.

No source-contract or scientific definition is changed. No synthetic result may
enter the package. Upstream native admission remains authenticated original
evidence, not a new model validator. Offline replay does not re-encode, repeat
SVD/coordinate measurements, train, prove GPU resume, or establish physical
second-host execution. It does not install the authoritative paper or publish
source. Preserve partial attempts on failure and perform no automatic retry.

Verify the new entry's operational/inventory controls separately. Until the real
upstream document exists, report this handoff as queued, not paper completion.
Read all current state/claim/publication protocols; old stopped controllers,
both GPU lease namespaces, protected-helper prohibition, prior GitHub 403 and
HF historical deletion denial remain untouched.
