# Real native GPU resume verification

Owner authority is the direct instruction “你有权做一切事情，目标是尽快完成任务”.
This work does not pause or replace any existing scientific worker or change its
source, data, protocol, numerical identity or evidence. The protected helper and
historical controller boundaries stay in force. No source publication is claimed.

Two fixed cases use the original seed-314159 AdamW-source branches, with AdamW
and Muon reset operators respectively. The input is each genuine checkpoint 313,
downloaded anonymously with forced content transfer at its already verified HF
revision. All 18 files per checkpoint must match the original externally bound
native seal, and the original CPU checkpoint reader must accept both full saves.

The production bound Trainer already has explicit resume hooks. A separate entry
loads the original source and complete 50K view, constructs the exact original
recipe, then invokes those hooks with the downloaded component binding. The only
logging change is `report_to=[]` with W&B disabled; no original run is updated.
The model, data, sampler, optimizer, scheduler, precision and component identity
must remain identical. No fresh-worker receipt or complete-five-save receipt is
forged. The output namespace is new and contains only the newly produced final
checkpoint and normal metadata; the four original earlier saves are not copied
into it to simulate a new complete run.

The step-313 prefix contains 40,064 groups. Resume uses the remaining **78 updates
/ 9,936 groups** (77 full global batches of 128 and the final tail of 80), retaining
the 391-update scheduler and original order. Each case waits for its whole six-run
training pool, all 84 BEIR tasks and all 30 stage probes. It then obtains all four
tokens in both original lease namespaces, with nonblocking all-or-nothing attempts.
Inherited FDs remain held until the actual ranks exit; there is no explicit unlock.

Acceptance requires four actual rank exits zero and a separate CPU process that
native-reads both original and resumed final checkpoints. Compare every one of
134 model tensors, the entire named optimizer state, scheduler state, all four
rank RNG states and the numerical Trainer counters. Tensor/array comparisons are
byte-exact; scalar comparisons have no tolerance. Elapsed times, logging history,
output paths and generated model-card text are not numerical state comparisons.

Any failure stops the new verification queue and preserves its source, input,
logs and partial output. There is no automatic retry, fallback to fresh training,
changed tolerance, changed scientific result or mutation of the original run.
The focused tests are synthetic operational controls, not genuine GPU evidence.
Success would establish two genuine same-host HF-download/native-GPU-resume cases,
not all checkpoints, the NorMuon primary path, or a physical second-host replay.
This engineering evidence does not belong in the manuscript narrative or appendix.
