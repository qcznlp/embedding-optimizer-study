# Isolated local-role training-completion evidence reader

This is a **prepared, CPU-only evidence adapter**, not an installed scientific
consumer, formal contract admission, functional recovery, source release or new
experiment. Its real input is the unchanged twelve-run campaign. This engineering
record belongs nowhere in the manuscript.

## Gap and implementation

The formal `PrimaryV3Contract.complete_run()`, `inspect_matrix()` and portable
`recorded_runs()` still require the old single-selection fingerprint/proof schema.
The frozen operational evaluation dispatcher instead authenticates the full
500k-row equivalence audit and two real completion-proof types. Neither original
reader nor guard was modified here.

[campaign_evidence.py](source/campaign_evidence.py) provides
`read_complete_training_population(local_root)`. It authenticates four externally
fixed anchors, 36 original worker/completion records and 132 native metadata files:
**172 files / 23,376,519 bytes, twelve recipes and sixty retained checkpoints**.
It returns the unmodified complete original rows for a future explicitly versioned
consumer, with original fingerprints, scopes, sources and false release flags.

- Ten runs retain their original start, exit-zero and view-verification evidence.
- Two NorMuon runs retain actual termination observations and deep artifact
  verification; their OS exit status remains **unobserved/null**, never inferred.
- The four anchors bind the original all-run admission, data-equivalence audit,
  recorded 56-file source assembly and operational evaluation authorization.
  Reading the last record does not issue any new execution authority.
- All run metadata and saved Trainer records are hashed against the original
  proof; every complete checkpoint inventory, expected recipe identity and
  original deep-check record is linked. **Model/optimizer tensor bytes and raw
  training data are not revalidated by this metadata reader.**
- Only explicit local roles are opened. Original absolute paths are provenance,
  not filesystem destinations. Extra paths, duplicate JSON keys, symlinks,
  inconsistent proofs and changing files are refused.

The existing complete telemetry/numerical replay was already done and was not
repeated. This adapter adds native proof-type authentication and a reusable local
role API; it does not recompute curves or replace scientific outcome admission.

## Portable inputs and usage

The 133 original admission/native files already exist in the immutable
[training-observation HF snapshot](../../../docs/training-analysis-restoration.md).
This archive adds only the other **39 unchanged original data records** under
[additional-records](additional-records/); source code is separate under `source/`.
These new records and reader are **local, not newly published to HF or GitHub**.
Copy this archive off-host separately before shutting down the machine.

After recovering the exact original HF prefix, compose a new local evidence tree:

```bash
CUDA_VISIBLE_DEVICES='' /usr/bin/python -B source/assemble_snapshot.py \
  /absolute/path/to/recovered/training-prefix \
  /absolute/path/to/this-archive/additional-records \
  /absolute/path/to/new-evidence-root
CUDA_VISIBLE_DEVICES='' /usr/bin/python -I -B source/campaign_evidence.py \
  /absolute/path/to/new-evidence-root
```

[assemble_snapshot.py](source/assemble_snapshot.py) binds the original immutable
transport manifest and every required input, writes only an absent destination,
and runs the evidence reader on the assembled tree. It performs no network call.
Preserve partial output on failure; do not rerun against an existing destination.
The original host-bound preparation script is provenance only, not the portable
entry and not a command to rerun.
